# Contributing to PhotonIDE

Thank you for your interest in contributing to PhotonIDE.

PhotonIDE is an open-source code editor project built with Python. Contributions, suggestions, bug reports, and ideas are welcome.

## How to Contribute

There are several ways to contribute to PhotonIDE:

- Report bugs or unexpected behavior.
- Suggest improvements or new features.
- Improve documentation.
- Submit code changes through pull requests.
- Review existing issues and proposed changes.

## Reporting Bugs

When reporting a bug, please include as much relevant information as possible:

- A clear description of the problem.
- Steps to reproduce the issue.
- Expected behavior and actual behavior.
- Your operating system and relevant environment details.
- Error messages or logs, when available.

Please avoid including passwords, API keys, personal information, or other sensitive data in reports.

## Suggesting Features

Feature suggestions are welcome.

When proposing an idea, explain the problem it addresses, how you expect it to work, and any relevant use cases.

Suggestions are proposals, not commitments to implement particular features.

## Submitting Pull Requests

Anyone may propose changes through a pull request.

1. Fork the repository.
2. Create a branch for your changes.
3. Make your changes and review them before submission.
4. Test your changes where practical.
5. Commit your work with a clear and descriptive message.
6. Push your branch to your fork.
7. Open a pull request against the appropriate branch of the PhotonIDE repository.
8. Explain what your changes do and why they are useful.

Link any related issues when applicable. Include screenshots or additional context when they help explain a change.

Pull requests may be reviewed, discussed, requested to change, or declined. Submitting a pull request does not guarantee acceptance or merging.

## Code and Documentation Guidelines

When contributing, please aim to:

- Keep changes focused and understandable.
- Use clear, descriptive names.
- Follow the existing project structure and conventions where practical.
- Avoid unrelated changes in the same pull request.
- Update documentation when your changes affect documented behavior.
- Avoid committing generated files, secrets, credentials, or local environment configuration.
- Explain any important design decisions in your pull request.

PhotonIDE is an evolving project, so some conventions may change as its structure develops.

## Commits

Please use clear commit messages that describe the change.

Examples:

- `feat: add file search`
- `fix: handle invalid file paths`
- `docs: clarify installation instructions`
- `refactor: simplify editor configuration`

These prefixes are suggestions rather than mandatory requirements.

## Before Submitting

Before opening a pull request, please:

- Review the changes you made.
- Remove accidental or unrelated modifications.
- Run any relevant tests or checks that are available.
- Confirm that you have not included secrets or private information.
- Describe any known limitations in your submission.

If the project does not yet provide a relevant test or check, explain what you were able to verify.

## Questions and Discussion

For questions, bug reports, and proposals, use the repository's available GitHub features where appropriate.

Please check existing issues and discussions before opening a duplicate report.

## Final Notes

Contributions are welcome, but all proposed changes are subject to review.

By submitting a contribution, you agree that your contribution may be distributed under the project's applicable license. Ensure that you have the right to submit the material you contribute.

Thank you for helping make PhotonIDE better.
