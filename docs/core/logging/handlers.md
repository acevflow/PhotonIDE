# Logging Handlers

## Overview

The `handlers.py` module manages the output operations of the PhotonIDE logging system. It initializes the logging destinations, prints formatted messages to the console, and writes messages to a log file when file logging is available.

## Responsibilities

- Create the directory used to store log files.
- Initialize a new log file.
- Print colored log messages to the console.
- Append log messages to the active log file.
- Validate severity levels before processing messages.
- Handle file system errors and disable file logging when necessary.
- Preserve console logging when file output becomes unavailable.

## API Reference

### `print_internal_error(message)`

```python
print_internal_error(message: str) -> None
```

Prints an internal logging error directly to the console.

This function bypasses file output so that errors involving the logging system can be reported without relying on the destination that may have failed.

**Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `message` | `str` | Description of the internal logging error. |

The message uses the `ERROR` severity, the `Logging` component name, a timestamp, and the configured error color.

**Example:**

```python
print_internal_error("Unable to access the log file.")
```

### `initialize_logging(logger)`

```python
initialize_logging(logger) -> None
```

Initializes the shared logging destinations.

The function creates a `logs` directory in the current working directory and generates a new log file using the filename provided by `get_file_name()`.

If directory creation fails, file logging is disabled, an internal error is printed, and a warning is sent through the supplied logger.

If log file creation fails, file logging is disabled and the error is printed to the console.

**Parameters:**

| Parameter | Description |
|---|---|
| `logger` | Logger instance used to record initialization messages. |

When initialization reaches the end of the function, it records a `Logger initialized` message.

**Example:**

```python
from . import handlers

handlers.initialize_logging(logger)
```

This is an internal operation normally called by `Logger` during its initial setup.

### `log_message(logger, name, message, level="info")`

```python
log_message(
    logger,
    name: str,
    message: str,
    level: str = "info",
) -> None
```

Formats and outputs a log message to the configured destinations.

**Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `logger` | Logger instance | Used to report internal file-writing errors. |
| `name` | `str` | Name of the component generating the message. |
| `message` | `str` | Content of the message. |
| `level` | `str` | Severity level. Defaults to `info`. |

**Processing sequence:**

1. Converts the severity level to lowercase.
2. Checks that the level exists in `config.VALID_LEVELS`.
3. Formats the message using `format_message()`.
4. Prints the message to the console using the associated ANSI color.
5. Appends the message to the log file if file logging is enabled.

**Raises:**

- `ValueError`: If the severity level is unsupported.

If writing to the log file fails, the function disables further file logging and reports the failure through the console. The original message is still printed before the file write is attempted.

**Example:**

```python
handlers.log_message(
    logger,
    name="Editor",
    message="Document saved successfully.",
    level="info",
)
```

This function is intended for internal use by the `Logger` interface.

## Output Destinations

### Console

Messages are printed using the ANSI color associated with their severity level. The terminal formatting is reset after each message.

Internal logging errors are printed directly through `print_internal_error()` to avoid depending on file output.

### Log file

The log file is created in the `logs` directory relative to the current working directory. Its name is generated by `get_file_name()`.

The file is initially opened in write mode and subsequently opened in append mode for each message. All messages are written using UTF-8 encoding.

## Error Handling

| Failure | Behavior |
|---|---|
| Cannot create the `logs` directory | Disables file logging, reports the error, and returns from initialization. |
| Cannot create the initial log file | Disables file logging and reports the error. |
| Cannot append a message to the log file | Disables further file logging and reports the error. |
| Unsupported severity level | Raises `ValueError`. |

Console output remains available when file logging is disabled.

## Dependencies

- `os` — Creates directories and constructs the log file path.
- `config.py` — Provides severity levels, ANSI colors, and shared logging state.
- `formatters.py` — Generates timestamps, filenames, and formatted messages.
- `logger.py` — Supplies the logger instance used by the handlers.

## Design Considerations

- **Separation of concerns:** Output operations are isolated from the public logging interface.
- **Console fallback:** File system failures do not prevent normal console output.
- **Shared configuration:** All handlers use the same logging state.
- **Standard library only:** No external dependencies are required.

## Limitations

- The log directory is relative to the current working directory.
- The active file is opened separately for each message.
- File logging is disabled after a handled file system error and is not automatically re-enabled.
- No log rotation, retention policy, or concurrent-write coordination is implemented.
