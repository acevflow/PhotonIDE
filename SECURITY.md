# Security Policy

## Reporting a Vulnerability

If you discover a potential security vulnerability in PhotonIDE, please handle the report responsibly.

**Do not publish sensitive vulnerability details in a public GitHub issue or pull request.**

If private vulnerability reporting is enabled for this repository, use GitHub's private vulnerability reporting feature to submit your report.

To check whether this feature is available, visit the repository's **Security** tab on GitHub.

If private reporting is unavailable, do not disclose exploitable details publicly. Check the repository for an available private reporting option before sharing sensitive information.

## What to Include

When submitting a vulnerability report, include as much relevant information as you can safely provide:

- A concise description of the suspected vulnerability.
- The affected component or files, if known.
- The conditions required to reproduce the issue.
- The potential security impact.
- Relevant logs, screenshots, or proof-of-concept material, provided they do not expose real credentials or other sensitive information.
- Any suggested mitigation, if known.

Please avoid including real passwords, API keys, personal data, or other secrets in your report.

## Scope

This policy concerns potential security issues affecting PhotonIDE and its associated project components.

Examples may include:

- Exposure or mishandling of sensitive information.
- Unsafe file operations.
- Vulnerabilities in application functionality.
- Unexpected execution of untrusted content.
- Dependency-related security issues that affect the project.

This list is illustrative and is not exhaustive.

## Responsible Disclosure

Please allow the project to assess a reported issue before publicly disclosing details that could put users at risk.

Do not exploit a suspected vulnerability beyond what is necessary to establish the issue. Do not access, modify, or disclose data belonging to others.

## Response and Disclosure

Reports may be reviewed based on the information provided and the project's available resources.

No response time, remediation deadline, or particular outcome is guaranteed. The project may request additional information to understand the report.

Once an issue has been assessed and appropriately addressed, disclosure can be considered in a way that reduces risk to users.

## Supported Versions

PhotonIDE is under development. A formal list of supported versions and security maintenance commitments has not been established.

Please identify the version or commit you tested when submitting a report.

## Policy Updates

This policy may be updated as the project develops and its security reporting process evolves.
